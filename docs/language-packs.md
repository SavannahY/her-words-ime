# 语言包

语言包把用词选择与输入法代码分开，方便一起补充和修正。默认中性包提供常用、尽量保留原意的表达；社群包提供自愿选择的借字、拆字等写法。安装社群包后仍需在输入法菜单手动切换，默认继续使用中性表达。

公开用例是使用证据，不是语言规范。输入法也不能只凭一个偏旁判断词语是否歧视，或准确识别所有引文、专名和上下文。需要引用原话、讨论词语本身或使用专业术语时，可以切换到“保留措辞”。

## 选择与编译

仓库根目录的 `language-packs.json` 为 `neutral` 和 `community` 选择对应的 `pack.json` 相对路径。路径相对清单所在目录解析。先验证清单与选中的词包，再编译：

```sh
python3 scripts/validate_packs.py --manifest language-packs.json
python3 scripts/compile_packs.py --manifest language-packs.json --output generated/her_rewrite_rules.lua
```

编译器输出 `generated/her_rewrite_rules.lua`，供输入法加载。贡献时编辑词包并重新生成；不要只改生成的 Lua 文件。验证和编译通过说明数据符合项目约定，词义、语境和真实输入候选仍需结合例子检查。

## `pack.json` 格式

文件使用 UTF-8 JSON。顶层字段如下：

| 字段 | 内容 |
| --- | --- |
| `format` | 固定为 `her-words-language-pack` |
| `version` | 固定为数字 `1` |
| `id` | 词包的稳定标识 |
| `name` | 用户可读名称 |
| `language` | 本版使用 `zh-CN`；繁体字形由 `variants` 与 `to_traditional` 表示 |
| `kind` | `neutral` 或 `community` |
| `license` | 固定为 `MIT` |
| `description` | 适用范围和措辞风格 |
| `sources` | 来源记录数组，每条含 `id`、`title` 和 HTTPS `url` |
| `entries` | 规则数组 |

每条规则包含：

| 字段 | 内容 |
| --- | --- |
| `id` | 包内稳定且唯一的规则标识 |
| `from` | 原词，至少两个字符 |
| `to` | 替代表达 |
| `match` | `exact` 或 `phrase`，见下文 |
| `pinyin` | 可选。原词的完整拼音音节，以小写和空格分隔，例如 `nv qiang ren`；用 `v` 表示 ü，不加声调 |
| `variants` | 可选；其他原词字形数组，例如简繁体；每项也至少两个字符 |
| `to_traditional` | 可选；繁体输出，需要人工核对，避免简繁混写 |
| `note` | 使用语境、读音或义项差异及已知边界 |
| `source_ids` | 引用本包 `sources` 中的来源标识 |
| `tests` | 测试数组，每项含 `input` 和 `expected` |

至少为每条规则提供一个正向例子，以及一个不应误改的例子。保护例子的 `input` 和 `expected` 相同。采用 `phrase` 时，还应提供词条出现在较长句子中的例子，检查替换后语法是否成立。

下面是一个中性包示例。来源支持“女强人”的包容性替换建议；完整拼音记录原词发音，不宣称目标词与原词同音。

```json
{
  "format": "her-words-language-pack",
  "version": 1,
  "id": "example-neutral",
  "name": "中性表达示例",
  "language": "zh-CN",
  "kind": "neutral",
  "license": "MIT",
  "description": "以完整词条提供中性表达。",
  "sources": [
    {
      "id": "un-zh",
      "title": "联合国中文性别包容性语言指南",
      "url": "https://www.un.org/zh/gender-inclusive-language/guidelines.shtml"
    }
  ],
  "entries": [
    {
      "id": "successful-woman",
      "from": "女强人",
      "to": "事业有成的女性",
      "match": "exact",
      "pinyin": "nv qiang ren",
      "variants": ["女強人"],
      "to_traditional": "事業有成的女性",
      "note": "这是近义措辞建议，两个表达读音不同；引用和作品名称可保留原话。",
      "source_ids": ["un-zh"],
      "tests": [
        {"input": "女强人", "expected": "事业有成的女性"},
        {"input": "女科学家", "expected": "女科学家"}
      ]
    }
  ]
}
```

## 匹配范围与误伤

`exact` 只在候选文字整体等于 `from` 或其 `variants` 时替换。它适合有专名歧义、句法变化或上下文依赖的词。例如，“寡妇”可提供中性候选，而“黑寡妇”应保留。

`phrase` 会匹配候选中的完整字串，包括较长句子中的该字串。它没有自动分词或语义判断能力，适合替换前后能自然嵌入同一位置的表达。例如，“妇孺皆知”替换为“众所周知”。使用前要考虑这些问题：

- “你妈的”既可作粗口，也可能是“你妈的生日”的一部分；采用 `exact` 可以避免这个子串误伤。
- “绿茶婊”替换成带“的人”的短语，若按 `phrase` 匹配“绿茶婊子”，会留下多余的“子”。要缩窄为 `exact`，或明确处理完整词形。
- “娘娘腔”与“阴柔气质”的句法不完全相同，不能保证在任意整句中直接互换。
- “雌竞”不能改成“女性互助”；需要描述竞争事实时，可提出合适的中性转述。法律、历史和人权语境中的“奴役”“强奸罪”也不能被淡化。

不接受 `女`、`妈`、`妇`、`奸` 等单字的全局改写。`from` 和 `variants` 的最少两字限制只是基本边界，多字词仍可能误伤，必须提供反例。好、妈妈、姐姐、婚姻、嫌疑人、正常职业称谓以及专名，都应能正常输入。

## 社群包与中性回退

社群规则的 `from` 必须在选中的中性包中有对应条目。这样，同一个输入在默认模式下有明确的中性回退，只有手动选择社群模式才使用社群写法。

如果新增的社群写法没有合适的中性替代表达，可以在中性包添加 `from` 与 `to` 相同的条目，保留原词作为回退，再在社群包提供可选写法。中性条目同样要有来源、说明和测试，不能用回退条目绕过单字限制。

借字、拆字写法的说明需分别写清原词和目标表达的读音、义项与语体。目标字存在于 Unicode 或某篇帖子中，并不代表它是原词的通行异体字。不要仅凭“换了偏旁”就声称读音、词义完全相同。

## 拼音与候选排序

`pinyin` 始终记录原词的拼音。目标表达读音不同，也不修改成目标词的拼音，更不把目标词当作原词的标准读音。

别名建议不能挤掉正常同音词首项。核对 `jian ren` 的“坚韧”、`ji du` 的“极度”、`sheng nv` 的“圣女”等例子。词包里的文字替换测试检验的是改写结果；候选排序需要结合输入法实际行为核对。

## 来源与许可

每条规则用 `source_ids` 关联至少一条公开来源。说明来源实际支持的是原词释义、问题背景、近义表达，还是社群写法用例；不要把项目自行提出的映射写成机构规定。

词包的原创规则、说明和测试按 MIT 许可贡献。外部网页仍有自己的版权，使用短说明与链接记录依据，不附带整篇文章或无权重新许可的词库。
